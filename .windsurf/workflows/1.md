# Senior Dev Professional Workflow

Workflow này định nghĩa quy trình làm việc chuẩn cho senior developer khi thực hiện bất kỳ task nào trong dự án.

## Phase 1: Requirement Analysis (Phân tích yêu cầu)

1. **Đọc kỹ requirements** - Hiểu rõ "what" và "why" trước khi đụng vào "how"
2. **Identify edge cases** - Liệt kê các trường hợp biên, lỗi tiềm ẩn
3. **Impact assessment** - Đánh giá ảnh hưởng đến các module khác
4. **Clarify ambiguities** - Hỏi lại PO/manager nếu yêu cầu không rõ ràng

## Phase 2: Technical Design (Thiết kế kỹ thuật)

1. **Architecture review** - Xác định pattern phù hợp, tránh over-engineering
2. **API contracts** - Định nghĩa interfaces, data structures trước khi code
3. **State management** - Plan cho data flow, caching, sync/async handling
4. **Security check** - Input validation, auth, sensitive data handling

## Phase 3: Implementation (Coding)

// turbo
1. **Setup test environment** - Viết tests trước (TDD) hoặc song song
2. **Write clean code** - Tuân thủ SOLID, DRY, meaningful naming
3. **Error handling** - Không bao giờ silent fail, proper error messages
4. **Logging & monitoring** - Thêm logs cho debugging và observability
5. **Performance check** - Query optimization, lazy loading, bundle size

## Phase 4: Quality Assurance (Đảm bảo chất lượng)

// turbo
1. **Unit tests** - Coverage > 80%, test happy path và edge cases
2. **Integration tests** - Verify flow end-to-end
3. **Manual testing** - Test UI/UX, responsive, cross-browser
4. **Code review checklist**:
   - [ ] Logic correctness
   - [ ] Security vulnerabilities
   - [ ] Performance bottlenecks
   - [ ] Code style consistency
   - [ ] Documentation updated

## Phase 5: Documentation & Handoff

1. **Update docs** - API docs, README, architecture decisions (ADRs)
2. **Deployment guide** - Environment variables, migration scripts
3. **Knowledge transfer** - Record loom video hoặc viết handoff notes nếu cần

## Phase 6: Monitoring & Iteration

1. **Production monitoring** - Check error rates, performance metrics
2. **User feedback loop** - Collect feedback, plan improvements
3. **Technical debt tracking** - Note các cải thiện cần làm trong sprint sau

---

## Code Review Standards

**Must check:**
- Input validation và sanitization
- Race conditions trong async code
- Memory leaks (event listeners, intervals, subscriptions)
- Accessibility (ARIA labels, keyboard navigation, color contrast)
- Mobile responsive
- Error boundaries và fallback UI

**Nice to have:**
- Performance profiling results
- Bundle size impact analysis

---

## Definition of Done

- [ ] Code đã được review và approve bởi ít nhất 1 senior dev khác
- [ ] Tất cả tests pass (unit + integration)
- [ ] Không có console errors/warnings
- [ ] Documentation đã cập nhật
- [ ] QA đã verify trên staging environment
- [ ] Performance không degrade > 10% so với baseline

---

## Emergency Hotfix Protocol

1. **Tạo hotfix branch** từ `production`, không phải `main`
2. **Fix tối thiểu** - Chỉ sửa bug, không refactor
3. **Test nhanh** - Smoke tests + regression tests liên quan
4. **Deploy ASAP** - Skip queue nếu critical
5. **Root cause analysis** - Viết post-mortem trong 24h sau deploy
6. **Backport to main** - Merge hotfix vào main để không bị mất

---

## Communication Guidelines

- **Daily standup**: Yesterday done, today plan, blockers
- **Blocker escalation**: Escalate trong 2h nếu không tự giải quyết được
- **Tech decisions**: Document trong tech spec hoặc ADR
- **Code review feedback**: Constructive, explain "why" not just "what"
- **Knowledge sharing**: Internal tech talks, documentation first
